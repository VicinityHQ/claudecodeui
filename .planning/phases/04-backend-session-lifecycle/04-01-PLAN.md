<task type="auto">
  <name>Task 2: Implement Dual Timeout Mechanism</name>
  <files>server/claude-sdk.js</files>
  <action>
Add timeout constants and handler functions after the session status functions:

1. Add timeout constants at module level:
   - INACTIVITY_TIMEOUT_MS = 60_000 (60 seconds per CONTEXT.md)
   - MAX_DURATION_MS = 600_000 (10 minutes per CONTEXT.md)

2. Add setupSessionTimeouts(sessionId, session, ws) function:
   - Return early if !session
   - Set session.inactivityTimer = setTimeout with INACTIVITY_TIMEOUT_MS
     - Callback: handleSessionTimeout(sessionId, 'inactivity', 'No SDK activity for 60 seconds', ws)
   - Set session.maxDurationTimer = setTimeout with MAX_DURATION_MS
     - Callback: handleSessionTimeout(sessionId, 'max_duration', 'Session exceeded 10 minute maximum duration', ws)
   - Set session.startTime = Date.now()
   - Set session.lastActivity = Date.now()
   - Set session.ws = ws (store WebSocket reference for timeout handler)
   - Log: `Timeouts armed for session ${sessionId}: inactivity=60s, max=10m`

3. Add resetInactivityTimer(sessionId) function:
   - Get session from activeSessions Map
   - Return early if !session
   - clearTimeout(session.inactivityTimer)
   - Set new timeout: session.inactivityTimer = setTimeout with INACTIVITY_TIMEOUT_MS
     - Callback: handleSessionTimeout(sessionId, 'inactivity', 'No SDK activity for 60 seconds', session.ws)
   - Update session.lastActivity = Date.now()
   - DO NOT touch maxDurationTimer - it never resets (per CONTEXT.md)

4. Add handleSessionTimeout(sessionId, reason, message, ws) function:
   - Get session from activeSessions Map
   - Return early if !session
   - Guard against race condition: if session.status is COMPLETE or ERROR, log and return (don't send duplicate errors)
   - Log: `Session ${sessionId} timeout: ${reason} - ${message}`
   - Call transitionSessionState(sessionId, SessionStatus.TIMEOUT)
   - Send structured error to WebSocket (if ws and ws.readyState === 1):
     ```javascript
     ws.send(JSON.stringify({
       type: 'claude-error',
       error: message,
       sessionId: sessionId,
       timeout: true,
       reason: reason,
       timestamp: new Date().toISOString(),
       category: 'timeout'
     }))
     ```
   - Clear both timers: clearTimeout(session.inactivityTimer), clearTimeout(session.maxDurationTimer)
   - DO NOT call SDK abort (per CONTEXT.md decision - let SDK continue in background)
   - Schedule delayed cleanup (5 seconds) to allow status queries:
     ```javascript
     setTimeout(() => activeSessions.delete(sessionId), 5000)
     ```

Note: The ws parameter is passed explicitly to avoid circular reference issues.
  </action>
