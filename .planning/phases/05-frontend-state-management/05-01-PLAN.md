  <name>Task 1: Add key prop to ChatInterface in MainContent.jsx</name>
  <files>src/components/MainContent.jsx</files>
  <action>
Add a `key` prop to the ChatInterface component in MainContent.jsx that changes when selectedProject changes. This forces React to unmount and remount ChatInterface with fresh state whenever the user switches projects.

The key should be based on `selectedProject?.name` (not session ID - session changes within same project should NOT trigger full remount; that's handled differently in Plan 02).

Pattern from research:
```jsx
<ChatInterface
  key={`project-${selectedProject?.name || 'none'}`}
  selectedProject={selectedProject}
  selectedSession={selectedSession}
  // ... other props
/>
```

Why key prop pattern:
- Automatically clears ALL state in ChatInterface (input, messages, loading, etc.)
- Handles nested state and refs without manual cleanup
- React's official recommended pattern for state reset on prop changes
- Simpler than manual useEffect cleanup which can miss edge cases

DO NOT use session ID in the key - session switches within the same project need different handling (preserve some state, handled in Plan 02).
  </action>

<task type="auto">
  <name>Task 2: Remove localStorage restoration of input/messages on mount</name>
  <files>src/components/ChatInterface.jsx</files>
  <action>
Update the useState initializers in ChatInterface to NOT restore from localStorage on mount. The key prop pattern means the component remounts fresh, and we want clean state - not restored drafts.

Current pattern (to change):
```jsx
const [input, setInput] = useState(() => {
  if (typeof window !== 'undefined' && selectedProject) {
    return safeLocalStorage.getItem(`draft_input_${selectedProject.name}`) || '';
  }
  return '';
});
```

New pattern:
```jsx
const [input, setInput] = useState('');
```

Similarly for chatMessages:
```jsx
const [chatMessages, setChatMessages] = useState([]);
```

Keep the useEffect that PERSISTS input/messages to localStorage (around line 3160-3173) - we still want to save drafts, just not restore them automatically on project switch.

Rationale:
- The key prop pattern gives us a fresh component on project switch
- Restoring from localStorage would defeat the purpose of state reset
- Draft persistence remains for crash recovery / page refresh (different from project switch)
- Users expect clean slate when switching projects, not old drafts appearing

Note: If a user wants their draft back, they can navigate to the project and the draft will be there (on page refresh), but switching projects should start fresh.
